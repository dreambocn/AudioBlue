# 日志系统评估

目标：依据当前源码评估运行期日志能否支持发布后排障，不修改业务代码。

## 步骤
- [x] 检查仓库规则、Git 状态及日志相关入口。
- [x] 核对运行期日志、异常处理、连接状态、设置与安装诊断的实际实现。
- [x] 给出具备源码锚点的结论与改进优先级，检查文档差异。

## 验收条件
- 区分运行日志、用户错误提示和安装/测试日志。
- 说明日志持久化、上下文、异常覆盖、隐私及测试的现状。
- 明确本轮仅做静态审查，未执行的运行验证不宣称通过。

## 评估结果
- 运行期主要依赖 OutputDebugStringW，未发现统一日志服务、日志文件、轮转、等级配置或诊断导出入口。
- 连接错误保留 ConnectFailure 与 HRESULT，界面支持本地化及错误码；这些是内存状态和用户提示，不是持久化日志。
- 枚举与断开异常存在静默回退；设置加载未区分首次无文件与配置损坏的诊断记录。
- App 的 XAML 未处理异常入口仅输出消息；未发现项目自带转储或原生终止诊断机制。
- 安装运行时具有独立 install-runtime.log，开发验证日志不能替代应用运行期日志。
- 优先补本地有界日志、关键连接操作关联及异常上下文；之后补脱敏诊断导出和按需崩溃采集。

## 本轮验证
仅静态审查，未构建、未运行测试、未操作蓝牙设备。git diff --check 通过；新增本评估文档，无业务代码变更。
