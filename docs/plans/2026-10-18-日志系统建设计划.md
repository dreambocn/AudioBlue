## 1. 目标与范围

建立可支持发布后排障的本地日志系统：用户复现问题后能够导出材料，开发者据此区分枚举失败、连接阶段失败、取消清理、外部掉线、设置与桌面集成故障。

必须满足：

- Core 不依赖 WinUI；主窗口与托盘继续使用同一个 ConnectionManager。
- 日志故障不改变连接结果、取消语义、配置回退和应用退出行为。
- 正常 UI 交互不等待文件写入；内存队列、单条事件、文件大小与保留范围都有边界。
- 默认在本机记录，写入前脱敏；不采集音频，不自动上传，不新增后台服务。
- 能明确判断日志是否完整、是否发生丢弃和存储降级，不能把“没有日志”当作“没有异常”。

首版交付包含基础日志、关键链路、诊断导出、非正常结束识别及崩溃排查手册。进程外自动崩溃采集器、远程平台、ETW 性能追踪与日志查看器作为后续独立能力，不阻塞首版验收。首版不承诺为所有崩溃生成调用栈或转储。

## 3. 模块与调用关系

采用项目内的轻量 C++ 实现，复用标准库、Win32 和系统 CNG，不新增运行时日志依赖。原因是当前需求集中在本地文件、有限事件字段与 Windows 生命周期；格式、脱敏和故障策略均需要项目自身掌控。ZIP 也不作为首版导出的必要依赖。

| 拟新增位置 | 职责 |
| --- | --- |
| `AudioBule.Core\DiagnosticsTypes.h` | 等级、事件编号、类型化字段、操作上下文、状态和结果类型 |
| `AudioBule.Core\Logger.h/.cpp` | 小型调用接口、上下文、事件校验、共享运行状态与生命周期管理 |
| `AudioBule.Core\LogWriter.h/.cpp` | 私有文件写入模块：有界队列、批量写入、轮转、恢复和清理 |
| `AudioBule.Core\DiagnosticPrivacy.h/.cpp` | 字段白名单、设备令牌、字符串边界和安全 JSON 编码 |
| `AudioBule.Core\DiagnosticExport.h/.cpp` | 截取日志快照、重解析与白名单导出、清单及不完整状态 |
| `AudioBule.App\DiagnosticsController.h/.cpp` | 原生设置交互、文件选择器、后台导出、详细日志时限和状态提示 |
| `tests\Logger.test.cpp` 等 | 通过公开接口验证行为；内部文件写入适配器用于故障注入 |
| `tools\diagnostics` | 隔离的性能、故障与按需崩溃排查脚本；不得在正常启动时运行 |

调用关系：App 持有 Logger 运行实例；Core/App 各模块持有可复制的 LogContext；调用方提交类型化事件；写入模块负责排队、格式与文件策略。导出模块读取安全快照；Controller 只处理用户交互，不接管连接状态。

### 3.1 接口契约

以下是接口职责约定，实施时用实际 C++ 类型落实，不要求调用方拼接 JSON：

| 接口概念 | 契约 |
| --- | --- |
| `Logger(options)` | 建立共享状态并启动写入线程；目录与文件操作在后台执行；失败返回降级实例，不向业务抛异常 |
| `LogContext::Operation(trigger, deviceId)` | 生成会话内唯一操作编号、记录单调时钟起点；上下文按值跨线程传递 |
| `LogContext::Write(event, fields)` | 不做文件 I/O、不调用 UI 或业务回调；内部处理分配/编码失败；返回接受、过滤或丢弃状态 |
| `LogContext::WithDevice(rawId)` | 在进队列前转为会话内令牌，不能把原始设备 ID 放进事件字段 |
| `Logger::Status()` | 返回线程安全的内存快照：存储可用性、丢弃数、写入失败数、最后安全错误码 |
| `Logger::Snapshot(deadline)` | 控制消息不占普通事件配额；返回已封存日志片段和水位，不阻塞 UI |
| `Logger::Stop(deadline)` | 幂等；关闭接收、请求排空；返回完成/超时/存储失败，不能承诺所有事件都已保存 |

所有故障处理都不能递归调用日志接口。日志内部不反向获取 Manager、Provider、托盘或窗口的锁。

LogContext 默认构造为关闭状态，便于现有测试和不需要日志的调用方使用；不使用可变全局单例或线程局部变量隐式传递操作编号。测试可以独立创建 Logger，避免多测试相互污染。

Settings 函数、Provider、Manager 和系统集成模块通过显式构造参数或函数参数接收上下文。Provider 的同步调用接口增加诊断上下文参数，同步更新 FakeDeviceProvider 与所有调用点；该参数只传递诊断信息，不改变连接结果结构或 UI 状态来源。

## 4. 日志事件与格式

使用 UTF-8 无 BOM 的 JSON Lines，每行一个完整 JSON 对象；固定模板消息使用中文，事件编号、字段名与枚举值保持稳定，界面语言切换不影响日志解析。

| 字段 | 约定 |
| --- | --- |
| `schema_version` | 首版为 1；导出器按版本验证，未知版本不能原样转发 |
| `timestamp_utc` | UTC 时间，含毫秒，格式为 ISO 8601 |
| `elapsed_ms` | 相对进程启动的单调时钟时间；操作结束另有 `duration_ms` |
| `session_id`、`sequence` | 每次进程运行随机会话编号；写入线程分配唯一顺序号；内部另维护入队水位供快照使用 |
| `pid`、`tid` | 事件产生进程与线程，写入线程不能覆盖产生线程编号 |
| `level`、`module`、`event` | 等级、固定模块、稳定事件编号，例如 `connection.open_failed` |
| `operation_id`、`related_operation_id` | 当前操作与相关连接操作，非操作事件允许为空 |
| `trigger`、`stage` | manual/startup/system 等触发源；create/start/open/cleanup 等阶段 |
| `device_token` | 会话内匿名关联标记；不包含原名、蓝牙地址或原始 ID |
| `state_before`、`state_after` | 逻辑状态迁移，不能推导为正在播放 |
| `failure`、`hresult`、`win32_error` | 区分项目失败分类、HRESULT 和原始 Win32 错误；代码使用固定宽度十六进制 |
| `message`、`fields` | 由事件字典生成的中文模板及类型化白名单字段，不接受任意对象序列化 |

每个事件定义允许的字段、必需字段、默认等级及模板。单字段字符串最多 512 个 UTF-8 字节，单事件含换行最多 4 KiB；超限在字符边界截断并标记。修复或替换非法 Unicode，正确转义引号、反斜线、控制字符，避免一条输入伪造多条日志。

固定上下文如应用版本、构建架构、构建类型、受支持的系统版本信息和打包身份类型放在 `app.session_started` 与导出清单中，不在每行重复。不记录完整可执行路径、包安装路径、完整命令行或环境变量。

### 4.1 等级与频率

- Debug：阶段开始、重复请求被忽略、诊断扫描细节；默认过滤。
- Info：启动/退出、正常枚举摘要、操作终态、取消和清理结果、外部连接关闭。
- Warning：可恢复的连接失败、配置损坏、通知不可用、降级与限流摘要。
- Error：操作异常、配置无法保存、托盘初始化失败、日志存储持续失效。
- Critical：已观察到的未处理异常；不意味着日志一定来得及持久化。

首版正常运行使用 Info；设置页“临时开启详细日志”提升至 Debug，15 分钟后或进程退出时恢复。开关不写入长期设置；不增加 Trace，也不因 Debug 模式放开隐私限制。

同一模块、事件与错误码的重复告警按 60 秒窗口聚合：保留首次和恢复事件，窗口结束记录重复次数。聚合表最多 256 项，满后使用汇总计数。音频会话扫描只在匹配结果、失败类别或恢复状态变化时输出，禁止每秒重复写入。

## 5. 队列、写入与故障策略

### 5.1 默认边界

| 参数 | 首版默认值 |
| --- | --- |
| 队列 | 最多 2048 条且载荷最多 4 MiB，任一达到即视为满 |
| 高等级预留 | 总容量内预留 256 条及 512 KiB 给 Warning 及以上；低等级不能占用 |
| 批量写入 | 最多 128 条或 250 ms 一批；Warning 及以上唤醒写入线程 |
| 单文件 | 最多 4 MiB；写入下一条前判断轮转，禁止无限增长 |
| 每会话 | 当前文件加 4 个归档，合计不超过 20 MiB 日志载荷 |
| 历史保留 | 默认 7 天；日志根目录目标总量 100 MiB，优先删除最旧非活动会话 |
| 快照/退出等待 | 调用方后台等待最多 2 秒；超时返回明确状态 |
| 诊断导出 | 最多 20 MiB，优先本会话及最近故障；必须说明截断与排除项 |

队列为固定容量存储及短临界区，生产者不等待空位。满时低等级直接丢弃，高等级优先使用预留区域；全部占满时也允许丢弃，维护按等级的计数。恢复容量后由写入线程生成 `diagnostics.events_dropped` 摘要，不通过同一个满队列递归提交。正常运行不能声称 Error 永不丢失。

只允许写入线程访问文件和轮转元数据，队列锁内不执行格式化、CNG、目录操作或文件 I/O。状态锁内仅提取安全快照，业务事件在原有锁外通知；必要的日志入队也移到业务锁外。sequence 表示写入顺序，elapsed_ms 表示发生时间，不能把多线程文件顺序当成状态因果关系。

### 5.2 路径、多实例与清理

路径为解析后的当前用户本地应用数据目录下 `AudioBule\Logs\<session_id>\`；尊重现有冒烟测试的进程级 LOCALAPPDATA 隔离。无法得到有效绝对目录时关闭文件输出，禁止回退到工作目录或 EXE 安装目录。

每个进程拥有独立会话目录与排他持有的活动标记句柄；不共写一个 `app.log`。历史清理由跨进程互斥保护；只匹配已知会话和文件命名，检查规范化路径与重解析点，不沿链接递归删除。拿不到清理锁就跳过，不等待 UI。

100 MiB 是多实例下的保留目标：不删除其它进程正在使用的目录，所以并发活动会话可能暂时超过总量目标；每会话上限仍然成立。失效会话的标记、尾部信息也纳入清理，数量与遍历批次有上限。

### 5.3 存储失败与持久性

磁盘满、目录拒绝访问、轮转或写入失败时：

1. 捕获错误并更新内存状态、丢失计数，不改变业务结果。
2. 退避重试，间隔 1、5、30 秒，此后最多每 30 秒一次；未重试前不因每条事件反复打开文件。
3. 队列保持有界；额外保留最多 64 条已脱敏高等级事件作为内存尾部，不因持续故障无限增长。
4. 设置页显示“日志存储不可用”，恢复后记录恢复和缺失摘要；不逐条弹通知。
5. 调试输出只作为可选镜像，由写入线程执行并遵守同样的模板和脱敏规则；不作为持久化兜底保证。

正常批次写入后，最多每秒请求一次系统缓冲区刷新；显式快照与正常停止请求刷新。完成状态区分“写入成功”和“刷新失败”。断电、强杀或崩溃可能丢失最后一段日志，不能承诺零丢失。

### 5.4 停止与对象存活

Logger 的运行状态由日志上下文和写入线程共享持有；写入线程不持有 App、窗口、Provider 或 Manager 指针。

App 中新增私有 `ConnectionRuntime` 所有者，内部按 Provider、Manager 的顺序持有这两个对象；App 用 unique_ptr 管理它并替换现有直接成员访问。Logger 在该所有者之前声明与创建，先初始化日志上下文，再传给 Provider 和 Manager。这样正常退出可以显式销毁连接资源，异常析构路径也保持日志最后释放。

正常退出顺序固定为：阻止新请求并停止详细日志计时 → 取消/结束诊断导出并释放快照 → 退订业务事件并停用托盘/快速面板 → 按现有逻辑等待刷新、启动项及连接操作 → 取得已连接设备快照并保存设置 → 在正确线程释放音频会话标识与桌面集成资源 → 在后台销毁 ConnectionRuntime → 提交 `app.shutdown_completed` → 后台停止 Logger → 回 UI 完成窗口关闭与 Exit。不能在仍有业务清理日志产生时停止 Logger；后台步骤与 UI 步骤通过现有协程切换衔接。

最终关闭窗口后产生的迟到回调必须被现有停止状态挡住；仍持有 LogContext 的回调只得到关闭结果，不能访问已析构运行实例。新增测试覆盖这些时序。日志超时不能成为强制取消蓝牙任务、跳过已有清理或改变设备连接状态的理由。

停止期间拒绝新的普通事件；记录拒绝计数。2 秒超时后允许放弃尾部保存，但不能使用无限期 join 阻塞 UI，也不能强杀线程。实现需要可独立存活的共享写入状态：超时线程只继续处理自身资源，最后自行退出；线程对象由安全回收路径处理，必要时 detach，并通过测试证明没有悬空指针、joinable 析构终止或静态析构依赖。

文件 I/O 本身可能被系统长时间阻塞，因此这里只保证调用方等待有界，不保证后台线程在固定时间内结束。超时情况下不能写入“完整结束”持久标记。

## 6. 操作关联与埋点清单

Manager 为每次实际操作生成 OperationContext，显式传给 Provider 并按值捕获到线程。增加私有诊断元数据，不在 ConnectionEntry 中混入日志所有权，也不建立第二套连接状态。

每个已接受连接请求的终态事件最多生成一次；取消立即记录请求已撤销，底层完成并清理后才记录该操作终态。迟到成功、迟到失败、清理失败都关联原操作。成功连接的关联编号保留至底层关闭，关闭事件可以引用原连接编号。

| 范围 | 必须记录的事件与上下文 |
| --- | --- |
| 启动 | session_started、normal/startup 激活类型、支持性探测结果、初始化完成或失败 |
| 枚举 | 开始/结束、数量、耗时、unsupported/empty/error 的明确区别；异常记录安全错误码 |
| 手动/自动连接 | 请求来源、重复请求忽略、设备不存在、create/start/open 阶段、原始 Open 状态、归一化失败分类及 HRESULT |
| 连接终态 | succeeded/failed/cancelled、失败阶段、耗时、状态前后值；失败摘要在默认 Info 模式也足够定位阶段 |
| 取消 | cancellation_requested、底层仍在途、迟到结果丢弃、清理开始/结束与失败；清理结束前同设备仍不能重试 |
| 断开 | 用户请求、Close 结果、异常但 UI 保持既有状态、重复请求忽略 |
| 系统关闭 | connection_closed_observed；若能关联到本地主动关闭则记录关联，否则原因记 unknown，不推测手机断电或超距 |
| 设置 | 首次无文件为 Debug；读取失败、损坏、超限为 Warning；保存失败记录阶段和错误码，不写 JSON 内容和完整路径 |
| 启动项/通知 | 请求、结果、系统策略拒绝、注册/发送/注销失败；不写完整注册表值和通知正文 |
| 托盘/窗口/资源 | 初始化、Explorer 重建后恢复结果、消息异常、图标回退、资源缺失键；不逐次记录鼠标或重绘 |
| 音频会话标识 | 唯一匹配/重名回退/无匹配的变化摘要、修改和恢复 HRESULT；不输出会话显示名、实例标识和原始图标路径 |
| 退出 | shutdown_requested、等待在途数量与耗时、资源清理结果、日志停止结果 |

最靠近失败的层记录阶段详情，Manager 记录操作终态；上层只记录自身失败，避免同一异常在 Provider、Manager、App 连续输出三次相同堆栈或消息。捕获时及时保存 GetLastError/HRESULT，不能先调用日志再取错误码。

本次埋点不改变 Refresh 的空列表回退、Disconnect 的 UI 行为和既有错误文案。若后续需要改变这些交互，单独立项并增加状态契约测试。

## 7. 隐私与安全格式

- 设备令牌使用进程会话随机密钥和 HMAC-SHA256，截取 128 位作为标记；密钥仅在内存中，退出清除，不放进日志或导出文件。CNG 随机源或 HMAC 初始化失败时省略设备关联并标记不可用，不能回退为原始 ID 或无盐哈希。
- 令牌只保证同一会话内关联，重启后变化；不承诺跨会话追踪同一个设备。
- 原始设备名、MAC、用户目录、音频内容、配置正文、凭据和完整系统对象标识不进入队列、文件、调试镜像或导出。
- 不直接记录 `exception.what()`、WinRT Message 或 XAML args.Message：它们可能含路径、设备名或用户输入。默认记录异常类别、错误码和固定模板；确需补充内容时先定义字段白名单和测试。
- 源码位置只允许仓库相对路径或文件名；构建机绝对路径不进入发布日志。
- 导出按白名单重新构建记录，不能只用正则替换敏感字符串；未知字段/版本丢弃并统计。
- 日志和导出使用当前用户权限，不主动放宽 ACL，不写共享根目录；访问控制不等于加密，不宣称本地日志已加密。

更新 `PRIVACY.md` 中英文内容，说明默认本地记录、路径、留存、临时详细模式、手动导出及转储风险；README 增加反馈问题的具体步骤。

## 8. 原生诊断入口与导出

在现有设置页增加“诊断”区域，首版提供三项操作：

1. 打开日志文件夹：显示存储状态，目录不可用时给出本地化提示。
2. 临时开启详细日志：显示剩余时间，到期恢复 Info。
3. 导出诊断文件：说明仅保存本机，由用户自行决定是否分享。

使用原生文件保存交互，正确绑定主窗口；选择器取消不算错误。不新增托盘独立日志状态：托盘菜单沿用跳转设置，详细信息统一在设置页维护。

首版导出一个 UTF-8 `.jsonl` 文件：第一行是 `record_type=manifest` 的清单，后续是 `record_type=log` 的安全记录。清单包含版本/架构/系统、会话清单、时间范围、阈值、存储状态、丢弃数、跳过/截断数和快照结果，不包含用户名、机器名、路径或设备原始数据。该格式无需压缩库，PowerShell 和常见编辑器可直接读取。

导出流程：

1. UI 线程取得目标文件与强生命周期引用，随后转后台处理；同一时间只接受一次导出。
2. 请求写入线程封存当前片段并返回水位。等待超时则导出已完成片段，清单明确 `incomplete=true`。
3. 用受控快照句柄或等效 pin 机制防止导出期间被本进程轮转/其它实例清理；只枚举已知日志文件，拒绝重解析点和任意路径。
4. 逐行、限长解析并执行字段白名单，在具备 MTA 的后台线程调用 WinRT JSON 解析；无效行、未知版本和截断尾行计数后跳过。读取与导出总量有界，不一次加载全部文件。
5. 在目标同目录创建本次临时文件，成功后原子完成替换；失败或取消仅清理本次临时文件，不能破坏既有目标。
6. 回 UI 线程显示完整成功、部分成功或失败；仅捕获安全错误码，不把用户导出路径写回日志。导出进行中退出时先取消，并等待其释放快照后才进入日志停止；取消与 I/O 超时遵守共享状态独立存活原则。

不默认附带 settings.json、install-runtime.log、原始事件查看器记录或 dump。安装问题使用独立采集说明，避免把未脱敏的安装路径混入普通运行诊断包。

中英文资源同步新增诊断标题、说明、剩余时间、存储不可用、选择器取消以外的失败及不完整导出文案。验收键盘焦点、可访问名称、禁用/忙碌状态、语言切换、窄窗口及高 DPI。导出状态通过既有原生方式告知辅助技术，不能仅改变颜色。

## 9. 非正常结束与崩溃排查

### 9.1 首版内建能力

- 每个会话持有独立活动标记；正常完成业务清理和日志刷新后才写入结束标记。
- 下次启动只检查不再被活动进程持有且没有结束标记的会话，记录 `previous_session_unclean`。
- 未完整结束可能来自强制结束、系统关闭、断电或崩溃，统一标为“上次未完整结束”，不能直接断言崩溃。正常清理已完成但日志停止超时也要区分为记录不完整。
- XAML 未处理异常在安全上下文中尽力提交 Critical 类型与错误码，保留现有异常传播语义；不设置 Handled 来掩盖问题，不在回调中无限刷盘、等待日志线程或弹诊断窗口。
- 不在首版增加全局 SEH 吞异常或在 terminate 中运行普通 JSON/锁/堆分配路径；不能承诺内存损坏和 fast-fail 时仍能记录。

### 9.2 按需转储流程

提供 PowerShell 排查脚本与手册，按 AudioBule.exe 单应用范围配置 WER LocalDumps，或使用独立进程捕获。脚本检查权限和既有设置，保存原值，只在用户明确执行采集时生效，并提供恢复；本计划编制及后续普通冒烟都不自动修改这些系统设置。

转储保存在任务隔离的 C 盘排查目录，限制数量并记录实际位置。dump 可能包含内存中的私人设备信息、路径及其它数据，不纳入普通导出，不上传公开 Issue。EXE/便携/MSIX、调试器附加及系统策略场景需分别验证，不能假定 WER 在全部环境都有效。

正式发布保留对应架构、构建版本、二进制哈希和 PDB 的匹配记录；符号作为受控构建产物保留，避免仅有 dump 却无法定位代码。若今后增加进程外自动采集器，需要独立审查打包、隐私、退出和防递归崩溃设计。

### 实现与设计的具体对应

- 通过 Logger 构造器启动后台写入，不增加第二个 Start 生命周期入口；固定事件字典只接受枚举、数字和 HMAC 设备令牌。
- 快照采用固定字节水位与禁止删除共享的只读句柄，不复制整个文件，也不要求每次导出先封存文件；轮转上限内被快照固定的文件会造成可见的短暂存储降级。
- 重复告警用固定事件数组聚合，容量小于原设计的 256 项；停止或窗口到期输出汇总。连接终态不参与抑制。
- UI、日志基础、写入、隐私与导出代码均保持 Core/App 分层；应用以 ConnectionRuntime 显式销毁连接资源，再停止日志。
- 导出保存使用工程已有 Windows App SDK 1.8 的 FileSavePicker，以 AppWindow.Id 绑定主窗口，不需要旧版 HWND 初始化适配。
- 原生冒烟增加可选 TestDiagnosticPicker，实际验证系统保存对话框、隔离目标路径和导出文件。对话框中的编辑输入使用原生通知，避免本机 Shell UI Automation 角色不一致造成误选；焦点断言先确认主窗口位于前台，应用不会抢占其它窗口焦点。
- 性能预热只验证当前存储可用及丢弃计数；历史日志超出导出预算会正确返回不完整标记，不应因此判定当前写入失败。
- 导出按当前会话优先和历史会话时间筛选，首版没有历史故障索引；快照以不完整标记说明超时、范围截断或存储受限，不承诺采集全部历史。
