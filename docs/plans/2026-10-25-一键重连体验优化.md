# AudioBule 一键重连与静默连接体验优化计划

日期：2026-10-25

## 目标

手机可能没有播放声音，因此保持“连接状态”与“是否检测到音频”独立。增加用户主动触发的一键重新连接，替代手动断开再连接；不以零峰值或静默时长判定失败，不增加无条件自动二次连接。

## 步骤与进度

- [x] 检查当前工作区与主窗口/托盘共享设备行，保留已有暂存和未暂存修改。
- [x] Core 增加完整的手动重连操作，覆盖关闭清理、重新打开、取消、重复请求、异常和设备消失。
- [x] 主窗口与托盘共用重连入口及状态，保持连接成功语义，补充中英文说明与可访问名称。
- [x] 增加模拟回归，验证没有播放信号也不会自动重连或显示连接失败。
- [x] 执行分层检查、x64 核心测试、双架构构建与适用的原生冒烟，并记录限制。
- [x] 核对差异并更新功能与验证文档，交付本地修改。

## 设计决策

- 在设备行右侧提供独立的“重新连接”图标按钮，主按钮继续承担连接/断开/取消职责。图标按钮保持窄窗口和托盘布局，并提供提示与可访问名称。
- 重连属于一次可取消操作：只有底层关闭完成后才能重新打开；失败不循环重试；用户取消后停止重建并清理迟到结果。
- 使用明确的“重新连接中”状态贯穿清理和打开阶段；保留共享快照、连接代次与既有生命周期保护。
- 未建立可靠的手机播放状态观测前，不添加暗示手机正在播放或链路故障的音频状态标签；通过简短说明帮助用户判断何时使用重连。
- 不替换正在运行的安装版，不主动操作用户的手机连接、音量、静音、启动项或输出路由。

## 验证补充

增加独立的原生重连控件冒烟，只有同时显式设置两个冒烟环境标志时才启用虚拟设备 Provider；生产默认仍使用真实 Provider。虚拟模式停用音频会话标识写入，不连接或修改真实蓝牙设备。该冒烟单独验证设备操作、取消和语言，不替代完整托盘登记、日志持久化及真实音频验收。

原生冒烟中嵌套菜单的激活不稳定，最终改为独立图标按钮并移除菜单及其额外生命周期处理。键盘触发重连后焦点交给取消按钮，快速面板保留原有失去激活即关闭的行为。状态刷新时只在窗口边界确实变化后调用 MoveAndResize，避免相同边界的重复设置扰动交互。
